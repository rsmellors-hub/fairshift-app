## What this shows

- **No false Paid.** Paid is set only when PayPal reports the item SUCCESS. Every error, refusal, DENIED, FAILED, UNCLAIMED or unknown result leaves the payout unpaid.
- **No duplicate payout.** Each payable has a deterministic `sender_batch_id`. Recovery after a timeout, internal error or "previous request in progress" reads or resends with the same ID, and DUPLICATE_ITEM adopts the original batch.
- **Timeouts and internal errors go to reconciliation**, never to failed or paid on a guess.

## Differences from PayPal's documentation (recorded, not hidden)

1. **ERRPYO035** held the connection without answering on 11 Nov (it returned 429 on 7 Nov). FairShift's handling is safe for both behaviours.
2. **ERRPYO018** on `GET /v1/payments/payouts/{id}` returns PayPal's fixed sample batch with status SUCCESS, not DUPLICATE_ITEM, on both 7 and 11 Nov. FairShift never adopts a batch it didn't create.
